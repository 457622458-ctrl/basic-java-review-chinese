1. Java 基础（Topic 01 + Topic 02）

1.1 Java 是什么：从源码到运行

你写的 Welcome.java 是源码（给人看）。javac 编译后得到 Welcome.class，里面是字节码（给 JVM 看）。运行时 JVM 把字节码翻译成当前操作系统的调用，所以同一份 .class 可以在 Windows / Linux / Mac 上跑——这就是"Write Once, Run Anywhere"（平台无关 / architecture neutral）。

Welcome.java --(javac 编译)--> Welcome.class (byte code) --(java 启动 JVM)--> 运行

必背概念（Topic 01 原话）：

  • Java 白皮书 1996 年 5 月发布，James Gosling 等 Sun 工程师设计。
  • Java 的设计目标：Simple, Object-oriented, Distributed, Multithreaded, Dynamic, Architecture neutral / Portable, High performance, Robust, Secure。
  • JRE（Java Runtime Environment）：给用户运行 Java 程序。
  • JDK（Java Development Kit）：给程序员开发，= JRE + 编译器/调试器等工具。
  • Java 三大版本：J2SE（标准版，客户端独立程序）、J2EE（企业版，服务器端 servlet/JSP）、J2ME（微版，手机等移动设备）。
  • Java 部分借鉴 C++，但做了简化和改进（没有指针运算、有垃圾回收）。

考点：判断题/填空题常问 "JDK 与 JRE 的区别"、"JVM 的作用"、"Java 是否编译型/解释型"（答案：先编译成字节码，再由 JVM 解释/即时编译执行）。

1.2 第一个程序：每个符号都要能解释

public class FirstSample
{
    public static void main(String[] args)
    {
        System.out.println("Hello!");
    }
}

逐项解释（Lab01 Q1 与 Topic02 都考）：

部分含义考点
public访问修饰符（access modifier），表示"外面的人可以使用这个类"还有其他修饰符：private、protected（Topic 04）
class FirstSample类名。Java 中一切代码都必须写在类里，包括 main类名约定首字母大写
static静态：main 属于类而不属于某个对象，所以不用 new 对象就能运行详见 2.9
voidmain 不返回任何值不是 int main()
main程序入口，JVM 固定找这个名字拼错就 "no main method"
String[] args命令行参数，是一个字符串数组见 1.3
System.out.println输出并换行；print 不换行System.out 是 java.lang.System 类的静态字段

文件名规则（高频考点）：

  • 一个 .java 文件里最多只能有一个 public 类。
  • public 类的名字必须和文件名完全一致（含大小写）：FirstSample.java ↔ class FirstSample。
  • Java 区分大小写（case sensitive）。
  • 一个文件里可以有多个非 public 类，但最多一个 public 类。

1.3 命令行参数 args

public class Main {
    public static void main(String[] args) {
        System.out.println(args[0]);   // 第一个参数
        System.out.println(args.length);
    }
}
// 运行：java Main Hello 123
// 输出：Hello
//       2

陷阱：如果程序期望 2 个参数而你只给了 1 个，运行 args[1] 会抛 ArrayIndexOutOfBoundsException（运行时错误，不是编译错误）。

1.4 包（package）与 import

为什么需要包：类多了会重名，包就是"类的文件夹/命名空间"，把相关的类分组。

package calendar;          // 必须是文件第一条语句（注释除外）

import java.util.Scanner;  // 只导入 Scanner 一个类
import java.util.*;        // 导入 java.util 包中所有类

规则：

  • 标准库分散在多个包里：java.lang（System、Math、String，无需 import，自动可用）、java.util（Scanner、ArrayList、Collections……）、java.io（File、PrintWriter……）。
  • 不写 package 的类属于"默认包（default package）"，不能从别的包 import 它。
  • 用包里的类有两种写法：写全名 java.util.Scanner，或者 import 之后写短名 Scanner。
  • 类的全名 = 包名 + 类名，如 java.util.Scanner。

考点（Lab02 风格）：import java.util.*; 中的 * 只导入"类"，不递归导入子包。

// 单行注释（同 C++）

1.6 数据类型：8 种基本类型 + 引用类型

Java 的类型分两大类，这是一切的基础：

（1）8 种基本类型（primitive types）——变量里直接存"值"：

类型字节范围/说明例子
byte1-128 ~ 127byte b = 100;
short2-32768 ~ 32767short s = 1000;
int4±21 亿（默认整数类型）int x = 689;
long8更大；字面量要加 Llong x = 2223123123L;
float4小数；字面量要加 Ffloat f = 1.5F;
double8小数（默认浮点类型），D 可省double d = 1.5;
char2单个 Unicode 字符，用单引号char c = 'A';
boolean—只有 true / falseboolean ok = true;

（2）引用类型（reference types）——变量里存的是"对象的地址（引用）"，类似 C++ 的指针：

String s = "Hello";              // String 是内置类
Day d = new Day(2016, 1, 20);    // 自己写的类
int[] arr = new int[5];          // 数组也是对象！
  • 引用类型的值 = 指向对象的引用；对象本身存在别处（堆 heap）。
  • "对象（object）" 与 "实例（instance）" 是同义词。
  • 引用类型可以是：标准库类（String、Math、Scanner）、自己定义的类（Day、Employee）、数组。

必背：int 是基本类型，Integer 是它的"包装类"（引用类型），二者不同（4.9 详述）。

1.7 变量、声明、初始化

int x;              // 声明
x = 689;            // 赋值
int y = 10;         // 声明 + 初始化
double salary;
boolean done;
Box box;            // Box 是类类型，box 是变量（引用）
Box aBox;           // 习惯：对象变量加 a 前缀
Box bxJewels, bxCoins;

命名规范：

  • 变量/方法：小写开头，驼峰 vacationDays、raiseSalary。
  • 类：大写开头，Day、Employee。
  • 常量：全大写，CM_PER_INCH。

三条铁律：

  1. 局部变量必须先初始化才能用（编译器会报 "variable might not have been initialized"）。
  2. 字段（field）不用初始化：Java 自动给默认值——数字 0、boolean false、对象引用 null。
  3. 同一作用域内不能重复声明同名变量；内层块也不能声明与外层同名的变量。

1.8 常量 final

public class MyApp {
    public static final double CM_PER_INCH = 2.54;   // 类常量（全类共享）
    public static void main(String[] args) {
        final double PI = 3.14159;                    // 方法常量（局部）
        // PI = 3.14;   // 编译错误：cannot assign a value to final variable
    }
}
  • final 变量只能赋值一次，"set once and for all"。
  • 常量名习惯全大写。
  • static final = 类常量（2.9、4.5 还会用到 final 修饰字段/类/方法）。

1.9 运算符全家桶

（1）算术运算符：+ - * / % += -= *= /= %=

整数除法与浮点除法是最容易考的点：

System.out.println(3 / 4);       // 0    —— 两边都是 int，整数除法，取商
System.out.println(3.0 / 4);     // 0.75 —— 有一边是 double，浮点除法
System.out.println(3 % 4);       // 3    —— 取余
System.out.println(-7 / 2);      // -3   —— Java 向零取整（不是 -4）
System.out.println(-7 % 2);      // -1   —— 余数符号跟被除数

除以零的区别（必背，Lab02/Lab10 都考）：

System.out.println(0 / 0);       // ArithmeticException: / by zero （运行时异常）
System.out.println(0 % 0);       // ArithmeticException: / by zero
System.out.println(12.0 / 0);    // Infinity
System.out.println(0.0 / 0);     // NaN
System.out.println(12.0 % 0);    // NaN
System.out.println(0.0 % 0);     // NaN
记住：整数除以 0 → 抛异常；浮点除以 0 → Infinity / NaN，不抛异常。

（2）关系运算符：== != > < >= <=，结果是 boolean。

（3）逻辑运算符：&&（AND）、||（OR）、!（NOT），短路求值（short-circuit）：

if (isMember == true || calculateAge(...) >= 65)   // 左边真，右边不执行
if (totCourses > 0 && totalMarks / totCourses >= 90) // 左边假，右边不执行（避免除零）

考点：短路是"第二个操作数根本不求值"，不只是"结果一样"。程序题里常用它避免 NullPointerException： if (s != null && s.length() > 0)。

（4）位运算符（对整数的二进制位操作）：

运算符名称例子
&AND0b1110 & 0b0110 = 0b0110
`\`OR`0b1000 \0b0001 = 0b1001`
^XOR（不同为 1）0b11111110 ^ 0b11111111 = 0b00000001
~NOT（按位取反）~0b0000 = 0b1111...
<<左移，低位补 0 = 乘 2ⁿ0b0001 << 4 = 0b00010000
>>右移（符号位补） = 除 2ⁿ-8 >> 1 = -4
>>>无符号右移（高位补 0）只对负数有区别

课堂原例（建议背下来，选择题照抄）：

int n1 = 0xFE;            // 0b11111110 = 254
int n2 = n1 ^ 0xFF;       // 0b00000001 = 1
int n3 = n2 << 4;         // 0b00010000 = 16

注意：&、| 作用在 boolean 上时不短路（两边都算），所以 && 与 & 在条件里不等价。

1.10 类型转换（conversion）与强制转换（casting）

自动转换（隐式，宽化，不丢信息）：

byte → short → int → long → float → double
                char → int → ...

规则（Topic02 的三种情况）：

  1. 合法且不丢信息：int → long → double，自动。
  2. 合法但丢精度：int → float（float 只有 24 位有效数字），自动但结果可能变。
  3. 合法但可能丢信息：int → char（4 字节 → 2 字节），必须显式强制转换。
int i = 97;
char c = (char) i;          // 'a'
System.out.println(i);      // 97
System.out.println(c);      // a

int big = 2147483647;       // Integer.MAX_VALUE
float f = big;              // 2.14748365E9  （精度丢了）
double d = big;             // 2.147483647E9
char ch = (char) big;       // 溢出成别的字符（只保留低 16 位）

考试问法："Why may int → char cause information loss?" 答：int 4 字节范围远超 char 的 2 字节（0–65535），超出部分会被截断。

boolean 不能和数字互转（C++ 可以，Java 不行）：

boolean b = true;
int i = 3;
b = i;    // 编译错误：incompatible types
i = b;    // 编译错误

1.11 优先级与结合性

表达式里运算符多于一个时，先按优先级（precedence），同级再按结合性（associativity）。

  • () 最高（想改变顺序就加括号）。
  • 单目 ! ++ -- > 算术 * / % > + - > 关系 < > <= >= > == != > && > || > 赋值 = += ...。
  • 赋值是右结合：a = b = 10; 等价于 a = (b = 10);
  • 算术、关系是左结合：1234 / 100 / 10 = (1234/100)/10 = 12；1234 * 60 % 24 = (1234*60)%24。

课堂练习答案：

  • 1234 / 100 / 10 → (1234/100)/10 = 12/10 = 1
  • 1234 * 60 % 24 → (1234*60) % 24 = 74040 % 24 = 0
  • a = b = 10 → 右结合，先 b = 10，再 a = 10，两者都是 10。

易错：instanceof 的优先级低于关系运算、高于 &&；不确定就加括号。

1.12 String 字符串（重点！）

是什么：String 是不可变的字符序列（UTF-16 code units），是引用类型，但用起来像基本类型。

String s = new String("Hello");   // 显式 new
String t = "Hello";               // 简写（常用），字符串字面量在常量池

必会方法：

方法作用例子
length()字符个数"Hello".length() → 5
charAt(i)第 i 个字符（0 开始）"Hello".charAt(1) → 'e'
substring(a, b)从 a（含）到 b（不含）"Hello".substring(1,3) → "el"
indexOf(s)第一次出现的下标，找不到 -1"Hello".indexOf("l") → 2
equals(s)比较内容"abc".equals("abc") → true

split(regex)按正则切分成数组"a,b".split(",")

String.valueOf(x)任意值转字符串
isEmpty()是否空串

必须掌握的两个陷阱：

（1）== 比的是引用（是不是同一个对象），equals 比的是内容：

String a = "Hello";
String b = "Hello";
System.out.println(a == b);        // true —— 同一字面量，指向常量池同一对象

String c = a.substring(0, 5);      // 运行时新建的字符串
System.out.println(c == a);        // false ！（内容相同，但不是同一个对象）
System.out.println(c.equals(a));   // true  ✔

结论：比较字符串内容永远用 `.equals()`。null.equals() 会崩，写成 "abc".equals(x) 或 x != null && x.equals("abc")。

（2）String 不可变（immutable）：

String s1 = "Everybody gets a good grade";
String s2 = s1.replace("a good grade", "an A+");
System.out.println(s1);   // Everybody gets a good grade  ← 原串没变！
System.out.println(s2);   // Everybody gets an A+

所有"修改"字符串的方法都返回新对象，原对象不变。想"改内容"只能重新赋值：

greeting = greeting.substring(0, 3) + "p!";   // 其实是新建了一个字符串对象

旧对象没人引用后由垃圾回收（Garbage Collection）自动回收。

空串 "" 长度 0，和 null 完全不同：

if (s != null && s.length() != 0) { ... }   // 既非 null 又非空

1.17 数组（Array）

是什么：一组同类型元素的集合，长度固定，下标从 0 开始。数组本身是对象，数组变量是引用。

int[] arr;                  // 声明（推荐写法）
// int arr[];               // 也能编译，但不推荐
arr = new int[5];           // 创建，长度 5，元素默认 0
arr[0] = 3;
arr[1] = 25;

for (int i = 0; i < arr.length; i++)   // .length 是字段（没有括号！）
    System.out.println(arr[i]);

三种写法：

int[] a;                       // (1) 先声明后创建
a = new int[5];

int[] b = new int[5];          // (2) 声明 + 创建 + 逐个赋值
b[0] = 3; b[1] = 25;

int[] c = {3, 5, 0, 0, 0};     // (3) 声明 + 初始化列表（简写）

默认值：数字 0、boolean false、对象元素 null。

长度不可变：想要"变长"，只能新建一个更大的数组再拷贝：

arr = new int[] {1,2,3,4,5,6,7,8};   // arr 指向新数组，旧的被 GC 回收

for-each 循环：

for (int x : arr)
    System.out.println(x);

注意 for-each 里的 x 是元素的副本，改 x 不会改数组本身。

常用工具（`java.util.Arrays`）：

System.out.println(Arrays.toString(arr));   // [3, 5, 0, 0, 0]
Arrays.sort(arr);                           // 升序排序（原地）
int[] copy = Arrays.copyOf(arr, 4);         // 拷贝出长度 4 的新数组（截断/补 0）
int[] part = Arrays.copyOfRange(arr, 1, 3);// 拷贝下标 [1,3)
Arrays.fill(arr, 7);                        // 全部填 7
System.out.println(Arrays.equals(a, b));    // 比较内容

拷贝的两种含义（必考）：

int[] arr1 = {3, 25, 0, 0, 0};
int[] arr2 = arr1;                    // 只拷贝引用！两个变量指向同一个数组
int[] arr3 = Arrays.copyOf(arr1, 5);  // 真正新数组

arr1[1] = 99;
// arr1 = [3,99,0,0,0]
// arr2 = [3,99,0,0,0]  ← 同一个数组，跟着变
// arr3 = [3,25,0,0,0]  ← 独立副本

二维数组：本质是"数组的数组"（1D array of 1D arrays）。

int[][] table = new int[5][10];   // 5 行 10 列，默认全 0
table[3][5] = 1234;               // 第 4 行第 6 列

for (int[] row : table)           // 每一行是一个 int[]
    System.out.println(Arrays.toString(row));

锯齿数组（ragged array）：每行长度可以不同，Java 很容易做到：

String[][] helpers = {
    {"Helena", "Kit", "Jason"},
    {"Kit", "Jason"},
    {"Helena"}
};

常见异常：ArrayIndexOutOfBoundsException（下标越界，运行时错误）；NullPointerException（数组变量还是 null 就访问元素）。

2. 类与对象（Topic 03）

2.1 从"结构化编程"到"面向对象"

  • 结构化编程（structured programming）：先设计一组过程（函数），通常自顶向下，从 main() 开始拆。
  • 面向对象编程（OOP）：数据优先，先找"有哪些类"，再看"对这些数据做什么操作"。没有"顶层 main"的概念。

怎么找类？看需求描述里的名词（通常是类）；再看动词（通常是方法）。

课堂例子：Employee（员工）、Day（日期）、Scanner（扫描器）……都来自需求里的名词。

为什么 OOP 更适合大问题：

  1. 代码围绕数据组织，结构清晰；
  2. 数据出问题容易定位（"只有这个类的方法能改它"）；
  3. 封装使实现可替换而不影响使用者（2.7 详述）。

OOP 的核心词（概念题必考）：

术语中文定义
Class类创建对象的模板/蓝图（cookie cutter，饼干模子）
Object / Instance对象/实例由类创建出来的具体个体（cookie）
Instance field实例字段对象里的数据（如 day, month, year）
Object state对象状态某一时刻所有实例字段值的集合
Method方法操作数据的函数
Encapsulation封装把数据和操作数据的方法打包在一起，隐藏实现细节（information hiding）

2.2 第一个完整的类：Day

public class Day {
    // 实例字段（instance fields）：每个对象各有一份
    private int year;
    private int month;
    private int day;

    // 构造器（constructor）
    public Day(int y, int m, int d) {
        this.year = y;
        this.month = m;
        this.day = d;
    }

    // 返回 "dd MMM yyyy" 形式的字符串
    public String toString() {
        final String[] MonthNames = {
            "Jan","Feb","Mar","Apr","May","Jun",
            "Jul","Aug","Sep","Oct","Nov","Dec" };
        return day + " " + MonthNames[month - 1] + " " + year;
    }

    // 判断闰年（static 方法：不需要对象也能调用）
    public static boolean isLeapYear(int y) {
        if (y % 400 == 0) return true;
        else if (y % 100 == 0) return false;
        else if (y % 4 == 0) return true;
        else return false;
    }

    // 判断日期是否合法（static 方法）
    public static boolean valid(int y, int m, int d) {
        if (m < 1 || m > 12 || d < 1) return false;
        switch (m) {
            case 1: case 3: case 5: case 7: case 8: case 10: case 12:
                return d <= 31;
            case 4: case 6: case 9: case 11:
                return d <= 30;
            case 2:
                if (isLeapYear(y)) return d <= 29;
                else return d <= 28;
            default: return false;
        }
    }

    // 是否是本月最后一天（Lab01 Q2 用）
    public boolean isEndOfAMonth() {
        return day == daysInMonth(year, month);
    }

    private static int daysInMonth(int y, int m) {
        switch (m) {
            case 2:  return isLeapYear(y) ? 29 : 28;
            case 4: case 6: case 9: case 11: return 30;
            default: return 31;
        }
    }

    // 前进一天（Mutator：改变对象状态）
    public void advance() {
        if (isEndOfAMonth()) {
            day = 1;
            if (month == 12) { month = 1; year++; }
            else month++;
        } else {
            day++;
        }
    }
}

使用：

Day d1 = new Day(2014, 1, 28);
System.out.println(d1.toString());   // 28 Jan 2014
System.out.println(d1);              // 自动调用 toString()
d1.advance();
System.out.println(d1);              // 29 Jan 2014

格式说明：System.out.println(d1) 等价于 println(d1.toString()) —— 打印对象时 Java 自动调用 `toString()`（第 3 章详述）。

2.3 构造器（Constructor）

定义：一种特殊方法，用来创建并初始化对象。

四条规则（必背）：

  1. 名字必须与类名完全相同；
  2. 没有返回类型（连 void 都不写）；
  3. 只能通过 `new` 调用；
  4. 一个类可以有多个构造器（重载，见 2.11）。
public Day(int y, int m, int d) { ... }     // 3 参数构造器
public Day(int y, int nthDayInYear) { ... } // 2 参数构造器（重载）

不能这样"重新初始化"一个已存在的对象：

Day birthday = new Day(2014, 1, 15);
birthday.Day(2014, 1, 27);   // 编译错误：The method Day(int,int,int) is undefined for the type Day

因为构造器不是普通方法，只能跟 new 一起用。

默认构造器（default constructor）：如果一个构造器都没写，编译器自动生成一个"无参构造器"，字段取默认值（0 / false / null）。

public class Employee {
    private String name;
    private double salary;
    // 没写任何构造器 → 自动有 public Employee() {}
}
Employee e = new Employee();   // OK，name = null, salary = 0.0

一旦你自己写了任何构造器，编译器就不再自动生成无参构造器。这条在继承里会引发经典错误（3.5）。

2.4 对象、对象变量、引用、null（画图题核心）

关键认知：对象变量不装对象，装的是"指向对象的引用"（类似 C++ 的指针）。

Day birthday;                        // 变量存在，但还没有指向任何对象（局部变量必须先赋值）
birthday = new Day(2014, 1, 15);     // new 在堆里创建对象，把引用赋给变量

内存图像（考试画图就画这个）：

栈 (stack)                    堆 (heap)
+-------------+             +----------------------+
| birthday    | --------->  | Day object           |
+-------------+             |  year  = 2014        |
                            |  month = 1           |
                            |  day   = 15          |
                            +----------------------+

两个变量指向同一个对象：

Day birthday = new Day(2014, 1, 15);
Day deadline = birthday;        // 拷贝的是"引用"，不是对象！
deadline.advance();             // 改的是同一个对象
System.out.println(birthday);   // 16 Jan 2014  ← birthday 也变了
birthday ---+

deadline ---+

null：表示"不指向任何对象"。

Day d1 = null;
// d1.toString();          // NullPointerException（运行时错误）
if (d1 == null) { ... }    // 用前先判空

局部变量不会自动初始化（上一章强调过）：对象变量要么 null、要么指向已有对象、要么 new。

2.5 this 关键字与隐式参数

Employee number007 = new Employee("Harry", 50000);
number007.raiseSalary(5);

调用 number007.raiseSalary(5) 时其实有两个参数：

  • 隐式参数（implicit parameter）：number007，即"被调用方法的那个对象"（calling object），方法里用 this 表示；
  • 显式参数（explicit parameter）：5，即方法声明里列出来的 percent。
public void raiseSalary(double percent) {
    double raise = this.salary * percent / 100;   // this.salary 就是 number007.salary
    this.salary += raise;
}

this 的三种用法：

  1. 区分同名字段与参数（最常见）：
public Day(int year, int month, int day) {
    this.year = year;      // 左边是字段，右边是参数
    this.month = month;
    this.day = day;
}
  1. 在一个构造器里调用另一个构造器（必须是第一条语句）：
public Day(int y, int m, int d) { year=y; month=m; day=d; }
public Day(int y) { this(y, 1, 1); }     // 调用上面的 3 参数构造器
  1. 把当前对象传给别的方法：someMethod(this);

注意：this 只能用在非静态方法/构造器里。静态方法没有隐式参数，写 this 编译错误。

Lab01 的小结论：

  • 构造器 Day(int a, int b, int c) { this.year = a; ... } 参数名 a,b,c 可读性差（poor parameter naming），但能编译；
  • 如果参数名和字段名不冲突，this. 可以省略（不是必须）；
  • this 只能用于非静态方法/构造器。

2.6 封装（Encapsulation）与访问控制

思想：字段设为 private（只有本类能看），对外只暴露必要的 public 方法。使用者不需要知道内部怎么实现，只需要知道能调用什么。

public class Employee {
    private String name;       // 外部看不见
    private double salary;
    private Day hireDay;

    public String getName() { return name; }        // accessor (getter)
    public double getSalary() { return salary; }
    public Day getHireDay() { return hireDay; }

    public void raiseSalary(double percent) {       // 不是简单的 setter，而是"业务方法"
        double raise = salary * percent / 100;
        salary += raise;
    }
}

访问修饰符（access modifiers）总表（第 3 章还会展开）：

修饰符同类同包子类任何地方
private✔✘✘✘
（无修饰符）package-private✔✔✘✘
protected✔✔✔✘
public✔✔✔✔

2.7 封装的好处（必背三条）

  1. 保护数据不被误改：外部只能通过类提供的方法访问，方法里可以做检查（如工资不能为负）。
  2. 容易定位 bug：只有本类的方法能改这片数据，出问题就查这个类。
  3. 容易替换实现：例如 Day 原来用 year/month/day 三个 int，后来改成 int yyyymmdd —— 外部代码完全不用改。

2.8 "改实现但不影响使用者"的经典例子

// 旧实现
public class Day {
    private int year, month, day;
    public int getDay()   { return day; }
    public int getMonth() { return month; }
    public int getYear()  { return year; }
}

// 新实现：只用一个 int
public class Day {
    private int yyyymmdd;                       // 例如 20140115
    public Day(int y, int m, int d) { yyyymmdd = y*10000 + m*100 + d; }
    public int getDay()   { return yyyymmdd % 100; }
    public int getMonth() { return yyyymmdd % 10000 / 100; }
    public int getYear()  { return yyyymmdd / 10000; }
}

外部调用 d.getYear() 的代码一个字都不用改——这就是封装的价值，也是考试"Q: do users need to adjust their code? A: No"的标准答案。

2.9 static 关键字：类级别的字段与方法

（1）静态字段（static field）：整个类只有一份，不属于某个对象。

class Employee {
    private static int nextId = 1;   // 全类共享
    private int id;                  // 每个对象各有一份
    private String name;

    public Employee(String n) {
        name = n;
        id = nextId;                 // 用当前的 nextId
        nextId++;                    // 然后自增
    }
    public static int getNextId() { return nextId; }
}
  • 非静态字段：每个对象一份（name、id）。
  • 静态字段：所有对象共享一份（nextId）。
  • 访问方式：Employee.nextId、Employee.getNextId()（通过类名，不通过对象）。

Lab05 Q0 的陷阱题：

class X {
    private static int a;    // 静态
    private int b;           // 实例
    public X(int n) { this.a = n; this.b = n; }
    public void print() { System.out.printf("a is %d, b is %d\n", a, b); }
}
new X(1); new X(2); new X(3);
// 输出：a is 3, b is 1
//       a is 3, b is 2
//       a is 3, b is 3

因为 a 每次都被覆盖，最后只剩 3。

（2）静态方法（static method）：属于类，不属于对象。

  • 没有隐式参数，没有 `this`。
  • 什么时候用？
  1. 所有需要的信息都由参数传入，不需要访问对象状态（如 Day.isLeapYear(y)）；
  2. 只访问静态字段（如 Employee.getNextId()）。
public static boolean isLeapYear(int y) { ... }   // 调用：Day.isLeapYear(2024)
public static void main(String[] args) { ... }    // main 也是静态方法！

（3）静态方法不能直接访问非静态字段：

public static void foo() {
    System.out.println(name);   // 编译错误：non-static variable name cannot be referenced
}

（4）静态字段陷阱（Topic07 也考）：静态字段属于"泛型类本身"，不属于某个具体实例化类型。MobileDevice<Smartphone> 与 MobileDevice<Pager> 共享同一个 count。

2.10 方法参数：Java 只有"值传递"（call by value）

核心：方法拿到的永远是实参的副本。

  • 基本类型：复制的是值，方法里改副本，原变量不变。
  • 引用类型：复制的是引用，方法里可以通过副本改同一个对象的内容，但不能让原变量指向别的对象。
void swap(Employee e1, Employee e2) {
    Employee temp = e1;
    e1 = e2;
    e2 = temp;          // 只是交换了副本，调用者的 a、b 没变
}

void raise(Employee e) {
    e.raiseSalary(10);  // 通过副本找到同一个对象，改对象内容 —— 有效！
}

课堂图（Topic03 p14）：a 和 b 是对象变量；e1、e2 是它们的副本；改 e1/e2 不影响 a/b；但用 e1/e2 访问 salary 改的是同一个对象。

结论（必背）：Java 没有 C++ 那种引用传递；"对象传参能改对象内容"是因为引用被复制后仍指向同一对象。

2.11 方法重载（Overloading）与签名（Signature）

重载：同一个类里，方法名相同、参数列表不同。

void swap(Employee e1, Employee e2) { ... }
void swap(Day d1, Day d2) { ... }              // 参数类型不同 → 重载

public Day(int y, int m, int d) { ... }
public Day(int y) { this(y,1,1); }             // 参数个数不同 → 重载

签名 = 方法名 + 参数列表（参数的类型、个数、顺序）。

注意：返回类型不算签名的一部分！所以下面两个方法冲突：

public int getValue() { ... }
public double getValue() { ... }   // 编译错误：method already defined

编译器靠签名决定调用哪一个（编译期决定，叫 early binding）。

2.12 默认字段初始化 vs 局部变量

class Employee {
    private String name;      // 默认 null
    private double salary;    // 默认 0.0

    public Employee(String n, double s) { /* 故意什么都不做 */ }

    public static void main(String[] args) {
        Employee a = new Employee("Harry", 10000);
        System.out.println(a);        // null ($0.0) —— 没问题

        String s;
        int x;
        System.out.println(s);        // 编译错误：local variable s may not have been initialized
        System.out.println(x);        // 编译错误
    }
}

表格化记忆：

位置是否自动初始化
实例字段 / 静态字段✔ 数字 0、boolean false、引用 null
局部变量（方法内）✘ 必须先赋值
方法参数✘ 由调用者给

字段还可以在声明处初始化，甚至调用方法：

private double salary = 0;
private double randomSalary = Math.random() * 10000;

2.13 可变（mutable）与不可变（immutable）

  • mutable：对象创建后，还能通过方法改变内容（如 Day、Employee）。
  • immutable：创建后内容永远不能改（如 String、Integer 等包装类）。
String s1 = "Hello";
s1.replace("H", "J");        // 返回新串，s1 本身不变
System.out.println(s1);      // Hello

Integer x = 3;
x = 4;                       // 不是改对象，而是新建 Integer(4)，x 改指向它

为什么不可变好：可以安全共享、传参不用防御性拷贝；坏处是每次"修改"都新建对象。

2.14 getter/setter 的误区（概念题常考）

初学者以为"每个字段都要配 get/set"，这是错的：

  • 无脑加 getter/setter 等于把字段公开，破坏封装；
  • 应该"只在真正需要时"提供；
  • 更好的做法是提供业务方法，让对象自己做事情。

课堂例子：

  • Day 不该提供 setYear/setMonth/setDay：太容易被误用（把 2016-02-29 改成 2016-02-30）。
  • Rectangle 不必给 getX/getY，而是给 draw()。

原话："Don't ask for the information you need to do the work; ask the object that has the information to do the work for you."

还有个坑（Topic03 p11）：getter 直接返回可变对象，外部就能改内部状态：

public Day getHireDay() { return hireDay; }   // 危险！
...
e.getHireDay().setDay(1988, 1, 1);            // 外部直接改了员工的入职日期！

解决办法：返回一个副本（defensive copy），或返回不可变对象。

2.15 类设计的建议（Topic03 末尾）

  1. 字段一律 private。
  2. 一定要初始化数据（字段或构造器里）。
  3. 不要在类里用过多的基本类型（该建类就建类，如 Day）。
  4. 不是所有字段都需要 getter/setter。
  5. 把职责拆到合适的类里（一个类只做一件事）。
  6. 名字要能表达意图。

3. 继承与多态（Topic 04）

3.1 什么是继承

定义：在已有类的基础上创建新类，新类自动拥有旧类的字段和方法（可重用），还可以增加/修改。

  • 新类叫子类（subclass / derived class / child class）
  • 旧类叫父类（superclass / base class / parent class）
  • 关系是 "is-a"（是一个）：猫是动物，Tom 是猫，所以 Tom 也是动物。
  • 关键字：extends
class Employee {          // 父类
    private String id, name;
    private double salary;
    // 构造器、方法……
}

class Manager extends Employee {   // 子类
    private double bonus;          // 新增字段
    public double getBonus() { return bonus; }   // 新增方法
}

三条核心事实（Topic04 开篇）：

  1. is-a：子类对象也是父类对象（可以当父类用）。
  2. 复用（reuse）：父类的字段和方法子类都有。
  3. 重定义/覆盖（override）：子类可以重新实现父类的方法。

注意：构造器不会被继承。

3.2 UML 中的继承画法

        +-------------------+
        |     Employee      |      ← 父类（superclass）
        +-------------------+
        | - id: String      |
        | - name: String    |
        | - salary: double  |
        +-------------------+
        | + getSalary()     |
        | + toString()      |
        +-------------------+
                  ^
                  |   ← 实线 + 空心三角，箭头指向父类（"is-a"）
        +---------+---------+
        |      Manager      |      ← 子类
        +-------------------+
        | - bonus: double   |
        +-------------------+
        | + getBonus()      |
        | + toString()      |
        +-------------------+

符号速记：- private、+ public、# protected、~ package；继承 = 实线 + 空心三角（指向父类）；实现接口 = 虚线 + 空心三角（指向接口）。

3.3 访问修饰符与继承

类级别只能有两种：

  • public：任何地方可见；
  • 无修饰符：只在本包可见（package-private）。

成员（字段/方法）级别四种：

修饰符本类同包子类（可不同包）其他
private✔✘✘✘
无✔✔✘✘
protected✔✔✔✘
public✔✔✔✔

关键规则：

  • 子类不能访问父类的 private 成员（连继承都继承不到"可见性"）。
  • 子类覆盖方法时，可见性不能变小（只能相同或更宽）：父类 public，子类不能改成 private。
class A { public void f() {} }
class B extends A { private void f() {} }   // 编译错误：attempting to assign weaker access privileges
  • `protected` 字段是坏习惯：它破坏了封装（子类可以随意改父类数据，父类改实现时子类可能编译不过）。课堂原话："against the spirit of OOP"。protected 方法有时有用（如 clone()，表示"没准备好给普通人用，子类去实现"）。

3.4 继承中的字段/方法复用与覆盖

class Employee {
    private String id, name;
    private double salary;
    public String toString() { return id + " " + name + " " + salary; }
}

class Manager extends Employee {
    private double bonus;
    @Override
    public String toString() { return super.toString() + " " + bonus; }
}
  • super.toString()：调用父类版本的方法。
  • super 与 this 的区别：this 是本对象（可调用本类成员/构造器），super 是"父类那部分"（调用父类方法/构造器）。
  • 覆盖时建议加 @Override 注解：写错名字（如 tostring）编译期就会报错，而不是悄悄变成新方法。

覆盖（override）的规则：

  1. 方法名相同、参数列表相同、返回类型相同（或协变，子类型）；
  2. 可见性不能变小；
  3. 不能覆盖 final 方法；
  4. 不能抛出比父类更多的受检异常（第 5 章）。

重载（overload）vs 覆盖（override）：

重载覆盖
位置同一个类（或子类）子类覆盖父类
签名必须不同必须相同
决定时机编译期运行期（动态绑定）

3.5 构造器与 super()

构造器不会继承。但子类构造器里一定会调用父类构造器：

  1. 如果你写 super(参数)，就调用对应的父类构造器（必须是第一条语句）；
  2. 如果没写，编译器自动插入 super() —— 调用父类无参构造器。
class Employee {
    private String name;
    private double salary;
    public Employee(String n, double s) { name = n; salary = s; }
    // 注意：这里没有无参构造器！
}

class Manager extends Employee {
    private double bonus;
    public Manager(String n, double s, double b) {
        super(n, s);          // 必须显式调用，因为父类没有无参构造器
        bonus = b;
    }
}

经典报错：Implicit super constructor Employee() is undefined. Must explicitly invoke another constructor.

课堂的三个问题（Topic04 p6）：

情况结果
删掉子类构造器 B，保留调父类的 AOK
两个都删OK（Employee 自动有无参构造器，salary 为 0）
只删 A（调 super 的那个）编译错误：隐式 super() 找不到父类无参构造器

执行顺序：new Manager(...) → 先执行父类构造器（初始化父类字段）→ 再执行子类构造器。

3.6 多态（Polymorphism）与动态绑定（Dynamic Binding）

多态：同一个对象变量，可以指向不同实际类型的对象。

Employee e;              // 声明类型是 Employee
e = new Employee(...);   // 指向 Employee 对象
e = new Manager(...);    // 也合法！指向 Manager 对象（子类对象"是"父类对象）

动态绑定：调用非静态方法时，JVM 在运行时根据对象的实际类型选择方法版本，而不是根据变量声明类型。

Employee[] all = new Employee[3];
all[0] = new Employee("001", "Alice", 1000);
all[1] = new Manager("902", "Brian", 1000, 10);
all[2] = new Manager("904", "Daisy", 1000, 15);

for (Employee e : all)
    System.out.println(e);     // 自动调用各自实际类型的 toString()

输出：Alice 用 Employee.toString，Brian/Daisy 用 Manager.toString（多了 bonus）。

必背三条限制：

  1. 动态绑定只作用于实例方法；
  2. 字段不会动态绑定（编译期按变量类型决定）；
  3. static 方法不会动态绑定（按变量类型/类名决定）。
class A { public String s = "A"; public String f() { return "A.f"; } 
          public static String g() { return "A.g"; } }
class B extends A { public String s = "B"; public String f() { return "B.f"; }
          public static String g() { return "B.g"; } }

A x = new B();
System.out.println(x.s);   // A   ← 字段看声明类型
System.out.println(x.f());  // B.f ← 方法看实际类型
System.out.println(x.g());  // A.g ← static 看声明类型

（这三行是考试"看输出"的常客。）

多态的价值：调用者只依赖父类接口，新增子类时不用改调用代码——这就是 OCP（第 8 章）。

3.7 向上转型与向下转型（upcasting / downcasting）

向上转型（upcasting）：把子类对象当父类用。自动、隐式、一定安全。

Manager m = new Manager(...);
Employee e = m;            // 自动，不用写 (Employee)

用途：把 Manager 放进 Employee[] / ArrayList<Employee>。

向下转型（downcasting）：把父类引用转回子类类型。必须显式写 `(子类)`，可能运行期出错。

Employee e = all[2];              // 实际是 Manager
// e.getBonus();                  // 编译错误：Employee 没有 getBonus()
Manager m = (Manager) e;          // 显式向下转型
System.out.println(m.getBonus()); // OK

错误示范（ClassCastException）：

for (Employee e : all) {
    Manager m = (Manager) e;      // all[0] 是 Employee，不是 Manager
    System.out.println(m.getBonus());
}
// 运行时：Exception in thread "main" java.lang.ClassCastException:
//         class Employee cannot be cast to class Manager

正确做法：先用 `instanceof` 判断：

for (Employee e : all) {
    if (e instanceof Manager) {
        Manager m = (Manager) e;
        System.out.println(m.getBonus());
    }
}

`instanceof` 语法：x instanceof C，判断 x 指向的对象是否是 C 或 C 的子类实例，返回 boolean。

Object o1 = new Employee(...);
System.out.println(o1 instanceof Object);    // true
System.out.println(o1 instanceof Employee);  // true
Object o2 = "Hello";
System.out.println(o2 instanceof Employee);  // false

null instanceof 任何类 都是 false。

重要提醒：不要滥用 instanceof。如果你的代码里到处 instanceof 判断类型再调用不同版本方法，说明你该用多态+动态绑定了。课堂原话："Beginners often use instanceof in an unnecessary way... we should often let JAVA select the appropriate (redefined) method at run-time." 这正是 Lab06 的 OCP 主题。

3.8 final：类、方法、字段

用法含义例子
final class不能被继承final class Executive extends Manager {}
final method不能被覆盖public final String getName()
final field只能赋值一次（常量）public static final double CM_PER_INCH = 2.54;
final 局部变量常量final int N = 10;
final class StringSubClass extends String { }   // 编译错误：String 是 final 类
class Manager extends Employee {
    public String getName() { ... }              // 编译错误：不能覆盖 final 方法
}

Java 里 `String` 就是 final 类（不能有子类），这也是 String 能安全共享的原因之一。

3.9 抽象类（Abstract Class）

抽象方法：只有声明、没有实现的方法，用 abstract 修饰。

public abstract class Employee {
    private String name;
    public Employee(String n) { name = n; }
    public String getName() { return name; }
    public abstract double getPay();     // 没有方法体！
}

抽象类的规则（必背）：

  1. 含抽象方法的类必须声明为 abstract；
  2. 抽象类不能 `new`（不能实例化）；
  3. 但可以声明抽象类型的变量，让它指向具体子类对象；
  4. 子类必须实现所有抽象方法，否则子类也得声明为 abstract；
  5. 抽象类可以有构造器（给子类调用）；
  6. 抽象类可以没有抽象方法（只是不想让人实例化它）。
public class SalariedEmployee extends Employee {
    private double salary;
    public double getPay() { return salary / 12; }
}
public class HourlyEmployee extends Employee {
    private double rate, hours;
    public double getPay() { return rate * hours; }
}

Employee[] arr = new Employee[3];        // 可以：抽象类型数组
arr[0] = new HourlyEmployee("Helena", 52.5, 30);
arr[1] = new SalariedEmployee("Kit", 15000);
for (Employee e : arr)
    System.out.println(e.getName() + " ($" + e.getPay() + ")");   // 动态绑定

为什么需要抽象类：给一群"不完整的共同概念"提供统一类型和部分实现。Employee 这个抽象概念本身没有统一的"月薪算法"，所以 getPay() 只能留给子类。

`abstract` 不能用于：字段、构造器、静态方法。（静态方法与对象无关，无法多态。）

3.10 Object：所有类的"终极父类"

java.lang.Object 是每个类的祖先（不需要写 extends Object）。

Object o1 = new Employee("002", "Jim", 10000);
System.out.println(o1 instanceof Object);    // true
Object o2 = "Hello";
System.out.println(o2.getClass().toString()); // class java.lang.String

四个常用方法：

方法作用说明
toString()返回对象的字符串表示默认是 类名@哈希码，通常要覆盖
equals(Object)判断是否"相等"默认比较引用（同 ==），通常要覆盖成比较内容
getClass()返回运行时类对象常用于 equals 里比较类型
clone()复制对象protected，需实现 Cloneable（第 4 章）

toString：

class Employee {

equals 的正确覆盖模板（必背）：

public class SubjectResult {
    private String name;
    private char grade;

    @Override
    public boolean equals(Object otherObject) {
        if (otherObject == null) return false;                 // 1. 判空
        if (this.getClass() != otherObject.getClass()) return false;  // 2. 比较类型
        SubjectResult other = (SubjectResult) otherObject;     // 3. 转型
        if (!this.name.equals(other.name)) return false;       // 4. 字段比较（对象用 equals）
        if (this.grade != other.grade) return false;           //    基本类型用 ==
        return true;                                           // 5. 还可以 super.equals(...)
    }
}

常见错误：

public boolean equals(SubjectResult other) { ... }   // 参数写成了具体类型 → 这不是覆盖，是重载！

必须写成 equals(Object obj)，否则集合/框架调用的是 Object 的默认版本。加 `@Override` 可以立刻发现这个错误。

注意：覆盖 equals 时通常也要覆盖 hashCode（Java 约定：equals 相等则 hashCode 必须相等），否则放进 HashMap/HashSet 会出问题（第 7 章）。

3.13 继承的设计建议（必背）

  1. 把共有的字段和方法放到父类。
  2. 不要用 protected 字段（破坏封装）。
  3. 只在真正是 "is-a" 时才用继承；如果只是想复用一部分代码（<100%），不要继承。
  4. 覆盖方法时不要改变原有语义（父类说"返回工资"，子类不能返回"奖金"）。
  5. 多用多态和动态绑定，少用 instanceof 判类型。

4. 接口与内部类（Topic 05）

4.1 接口是什么：只规定"做什么"，不管"怎么做"

类比：接口像一份合同/规格说明书。它列出"必须提供哪些方法"，但不写代码；谁签了这份合同（implements），谁就必须把方法实现出来。

public interface IGrade {
    void readAnswer();   // 只有方法头，没有方法体
    void grade();
}

public interface IReadWrite {
    void readAnswer();
    void writeAnswer(int anAnswer);
}

语法要点（必背）：

  • 用 interface 而不是 class；
  • 方法默认就是 `public abstract`（不用写这两个关键字）；
  • 字段默认就是 `public static final`（接口不能有实例字段）；
  • 没有构造器（不能 new 接口）；
  • 一个类用 implements 实现接口，必须实现接口里所有方法，否则这个类要声明为 abstract。
public class Exercise implements IGrade, IReadWrite {
    private int studentAnswer;
    private char grade;

    public void readAnswer() { System.out.println("Student's answer is " + studentAnswer); }
    public void writeAnswer(int a) { studentAnswer = a; }
    public void grade() { grade = (studentAnswer == modelAnswer) ? 'A' : 'F'; }
}

4.2 接口的多实现与多继承

一个类可以实现多个接口（这是 Java 模拟"多继承"的方式）：

class Exercise implements IGrade, IReadWrite { ... }

一个接口可以 extends 多个接口：

interface T extends A, B { void f5(); }   // T 拥有 A、B、自己的所有方法

类只能 extends 一个类，但可以同时 extends 一个类 + implements 多个接口：

class Employee extends Person implements I1, I2 { ... }
class D2 extends D implements T { ... }

抽象类可以实现接口，但不实现全部方法（剩下的留给具体子类）：

abstract class C2 implements A {
    public void f1() { ... }     // 只实现一部分
    // 其余方法仍是 abstract
}

两个接口有同名方法，一个类同时实现它们 → 只写一个实现即可：

interface A2 { void f1(); void f5(); }
class X implements A, A2 {
    public void f1() { ... }     // 同时满足 A 和 A2
    public void f2() { ... }
    public void f5() { ... }
}

怎么选？（课堂给的标准答案）

倾向用抽象类，如果：

  • 想在几个紧密相关的类之间共享代码；
  • 子类会有很多公共方法/字段，或需要 protected/private 这种非 public 访问；
  • 想声明对象字段（让方法读写对象状态）。

倾向用接口，如果：

  • 预期不相关的类都会实现它（如 Comparable、Cloneable）；
  • 只想规定某种数据类型的行为，不关心谁来实现；
  • 想利用类型的多继承（一个类同时具备多种能力）。

4.4 经典例子：Grader / Student / Exercise（Lab06 前身）

需求：评分者只能读和打分，学生只能读和写答案。

interface IReadWrite { void readAnswer(); void writeAnswer(int ans); }
interface IGrade      { void readAnswer(); void grade(); }

class Exercise implements IGrade, IReadWrite {
    private final String question;
    private final int modelAnswer;
    private int studentAnswer;
    private char grade;

    public Exercise(String q, int a) { question = q; modelAnswer = a; }
    public void readAnswer()  { System.out.println("Student's answer is " + studentAnswer); }
    public void writeAnswer(int a) { studentAnswer = a; }
    public void grade() { grade = (studentAnswer == modelAnswer) ? 'A' : 'F'; }
    public void displayResult() { System.out.println("answer " + studentAnswer + ", grade " + grade); }
}

class Student {
    private String name;
    public Student(String n) { name = n; }
    public void doExercise(IReadWrite x, int ans) { x.writeAnswer(ans); }   // 只能看见读/写
}

class Grader {
    private String name;
    public Grader(String n) { name = n; }
    public void gradeExercise(IGrade x) { x.grade(); }                      // 只能看见打分
}

public class Main {
    public static void main(String[] args) {
        Exercise ex = new Exercise("What is 4! ", 24);
        Student m = new Student("Mary");
        Grader h = new Grader("Helena");
        m.doExercise(ex, 24);      // 对象以 IReadWrite 的身份传入
        h.gradeExercise(ex);       // 同一对象以 IGrade 的身份传入
        ex.displayResult();
    }
}

精髓：同一个 Exercise 对象，传给 Student 时被"窄化"成 IReadWrite（看不到 grade()），传给 Grader 时被窄化成 IGrade（看不到 writeAnswer()）。这叫用接口筛选功能。

4.5 Comparable 接口：让对象可排序

需求：Arrays.sort(arr) 和 Collections.sort(list) 怎么知道你的对象谁大谁小？—— 你必须告诉它两件事：

  1. 这些对象可以排序（实现 java.lang.Comparable<T>）；
  2. 怎么比较（实现 int compareTo(T another)）。
public class Employee implements Comparable<Employee> {
    private final String name;
    private double salary;
    private final Day hireDay;

    @Override
    public int compareTo(Employee another) {
        if (this.salary == another.salary) return 0;
        else if (this.salary > another.salary) return 1;
        else return -1;
    }
}

返回值约定：

  • 0：相等
  • > 0（通常 1）：this 比 another 大
  • < 0（通常 -1）：this 比 another 小

使用：

Employee[] arr = new Employee[3];
Arrays.sort(arr);                 // 数组排序
for (Employee e : arr) System.out.println(e);

ArrayList<Employee> list = new ArrayList<>();
Collections.sort(list);           // 列表排序

排序结果按 salary 从小到大。注意：compareTo 要跟 equals 保持一致（equals 为 true 时 compareTo 应返回 0）。

更简洁的写法（Java 7+）：

@Override
public int compareTo(Employee other) {
    return Double.compare(this.salary, other.salary);   // 或 Integer.compare(a,b)
}

4.6 Cloneable 接口：克隆对象（深浅拷贝）

先区分两个概念：

Employee e2 = e;          // 复制"引用"：e2 和 e 指向同一个对象（不是拷贝对象！）
Employee e3 = e.clone();  // 克隆：新建一个内容相同的对象

怎么让对象可克隆：

  1. 类实现 java.lang.Cloneable（这是个标记接口，没有方法，只表示"我允许被克隆"）；
  2. 覆盖 public Employee clone()（注意：Object 的 clone() 是 protected，要放宽为 public）。
class Employee implements Cloneable {
    private String name;
    private double salary;
    private Day hireDay;

    @Override
    public Employee clone() throws CloneNotSupportedException {
        Employee copy = (Employee) super.clone();     // 1. 先浅拷贝
        copy.hireDay = new Day(this.hireDay.getYear(), // 2. 再深拷贝可变子对象
                               this.hireDay.getMonth(),
                               this.hireDay.getDay());
        return copy;
    }
}

浅拷贝（shallow）vs 深拷贝（deep）：

  • Object.clone() 做的是逐字段复制（shallow）：基本类型复制值；引用类型只复制引用，新旧对象仍指向同一个子对象。
  • 如果子对象是可变的（如 Day），必须再克隆它一份，否则改一个影响另一个 → 深拷贝。
  • 如果子对象是不可变的（如 String），共享没关系，可以省掉。

对比图：

浅拷贝：  copy.hireDay ──┐
                          ├──> 同一个 Day 对象   ← 错！改一个影响另一个
          this.hireDay ──┘

深拷贝：  copy.hireDay ────> 新的 Day 对象（内容相同）
          this.hireDay ────> 原来的 Day 对象        ← 对

课堂的错误/正确代码对比（Topic05 p9）：

Employee e  = new Employee("Carl Cracker", 75000, 1987, 12, 15);
Employee e2 = e;             // 别名
Employee e3 = e.clone();     // 副本

e.getHireDay().setDay(1988, 1, 1);
e.setName("Helena");
e.setSalary(88000);

// 正确深拷贝时：
// e  : Helena 88000 1 Jan 1988
// e2 : Helena 88000 1 Jan 1988
// e3 : Carl Cracker 75000 15 Dec 1987   ← 完全独立

// 如果只浅拷贝（没重建 hireDay）：
// e3 : Carl Cracker 75000 1 Jan 1988    ← hireDay 被改了！

为什么 String 可以不深拷贝：String 不可变，"改名字"其实创建了新 String，原对象不受影响。

clone() 抛 CloneNotSupportedException（受检异常，所以要么 catch 要么 throws）。

4.7 内部类（Inner Class）

定义：写在一个类内部的类。

public class BankAccount {
    private class Money {          // 内部类
        private String currency;
        private double value;
        public Money(String c, double b) { currency = c; value = b; }
        public String toString() { return currency + " " + value; }
    }
    private Money balance;         // 外部类把内部类当字段类型
    public BankAccount(String currency) { balance = new Money(currency, 0.00); }
}

两个好处：

  1. 代码组织更好：辅助类（helper class）写在用它的类里面，不污染外面。
  2. 双向访问私有成员：
  • 外部类可以访问内部类的私有成员；
  • 内部类可以访问外部类的私有成员（连 private 都行）。
class BankAccount {
    private class Money {
        public String toString() { return currency + " " + value + " owned by " + owner; }
        //                                       ↑ 直接访问外部类的 private 字段 owner
    }
    private String owner;   // 外部类的私有字段
}

非静态内部类的对象必须"属于"某个外部类对象：在外部类的非静态方法里 new Money(...) 时，this（当前外部对象）自动成为这个内部对象的"外部对象"。

静态内部类：private static class InnerClass { ... }，与外部类对象没有关联（可以在静态方法里创建）。

其他事实：

  • 每个内部类编译后都有自己的 .class 文件（如 BankAccount$Money.class）。
  • 内部类可以是 private 或 public；public 时外面可以 account.new Money(...) 这样用（很少用）。
  • 非静态内部类里不能有非 final 的静态字段（private static int x; 编译错误；private final static int x = 3; 可以）。
  • 还有匿名内部类（anonymous class）：只想用一次、懒得命名，new 接口() { ... } 直接写实现——第 7 章 Comparator 会用。

5. 异常处理（Topic 06）

5.1 为什么需要异常

程序运行中可能出错：用户输入错、设备坏、磁盘满、数组越界……

传统做法：方法返回 -1、返回 null 表示出错 —— 缺点：调用者容易忘检查，且错误信息太少。

Java 的做法：出错时抛出一个异常对象（封装错误信息），

  • 当前代码段立刻退出；
  • 不返回任何值（哪怕方法返回类型不是 void）；
  • 沿着调用栈向上找"能处理这个异常的 catch 块"。

5.2 异常的层次结构（必背图）

                    Throwable
                   /         \
                Error       Exception
                              /      \
                    RuntimeException   IOException  ...
                    /            \          \
      ArithmeticException   NullPointerException   FileNotFoundException
      ArrayIndexOutOfBoundsException              ...
      ClassCastException
      InputMismatchException
      NumberFormatException
  • Throwable：所有错误/异常的祖先。
  • Error：JVM 层面的严重问题（OutOfMemoryError、StackOverflowError），合理程序不应该去 catch（虽然语法上可以）。
  • Exception：合理的程序可能想捕获的问题。
  • RuntimeException 及其子类：unchecked（非受检）。
  • 其他 Exception（如 IOException、FileNotFoundException）：checked（受检）。

5.3 受检 vs 非受检（checked vs unchecked）

Catch-or-Declare 规则：如果方法里可能抛受检异常，必须二选一：

  1. 用 try-catch 就地处理；
  2. 在方法签名用 throws 声明，把责任交给调用者。
// 方式 1：自己处理
public void read() {
    try {
        Scanner in = new Scanner(new File("data.txt"));
    } catch (FileNotFoundException e) {
        System.out.println("Cannot open the file.");
    }
}

// 方式 2：声明，让调用者处理
public void read() throws FileNotFoundException {
    Scanner in = new Scanner(new File("data.txt"));
}

5.4 try-catch-throw 机制

try {
    Scanner in = new Scanner(System.in);
    System.out.print("Input the file pathname: ");
    String fname = in.next();
    Scanner inFile = new Scanner(new File(fname));
    int x = inFile.nextInt();
    System.out.println("Data is: " + x);
    inFile.close();
} catch (FileNotFoundException e) {
    System.out.println("Cannot open the file.");
} catch (InputMismatchException e) {
    System.out.println("Cannot read the required number from the file.");
}
  • try 块：正常流程的代码；一旦某句抛异常，try 块剩下的语句不再执行，直接跳到匹配的 catch。
  • catch 块：参数是"异常类型 + 变量名"（习惯用 e）。
  • throw 语句：自己主动抛异常，throw new 异常类名(参数);
if (x < 0) {
    throw new NegativeIntegerException();
}

执行流程：

  1. 抛异常 → 2. 在 try 块中寻找匹配的 catch（按顺序）→ 3. 找到则执行 catch 块 → 4. 继续执行 try-catch 之后的代码。

5.5 自定义异常类

Java 标准库没有"负数输入"这种异常，自己定义：

public class NegativeIntegerException extends Exception {
    private int problemValue;

    public NegativeIntegerException() { super("Negative integer!"); }
    public NegativeIntegerException(String message) { super(message); }
    public NegativeIntegerException(String message, int v) {
        super(message);       // 调用父类构造器保存 message
        problemValue = v;
    }
    public int getProblemValue() { return problemValue; }
}

要点：

  • 继承 `Exception`（受检）或 RuntimeException（非受检）；
  • super(msg) 会把消息存起来，之后用 `e.getMessage()` 取出；
  • 习惯上提供"无参构造器 + 带详细消息的构造器"；
  • 可以加自己的字段和方法（如 problemValue）。

在方法里抛出 + 声明：

public static void processFile(String fname)
        throws FileNotFoundException, InputMismatchException, NegativeIntegerException {
    Scanner inFile = new Scanner(new File(fname));   // 可能抛 FileNotFoundException
    int x = inFile.nextInt();                        // 可能抛 InputMismatchException
    if (x < 0) throw new NegativeIntegerException(); // 主动抛
    System.out.println("Data is: " + x);
    inFile.close();
}

5.6 catch 的顺序：具体的在前，通用的在后

try {
    processFile(fname);
} catch (NegativeIntegerException e) {     // 具体的先
    System.out.println("Unexpected negative value.");
} catch (Exception e) {                    // 通用的后
    System.out.println("Some problem happens.");
}

如果写反了（先 Exception，再 NegativeIntegerException），编译错误：

Unreachable catch block for NegativeIntegerException. It is already handled by the catch block for Exception.

原因：Exception 已经能捕获所有子类，后面的 catch 永远到不了。

单个 catch 捕获多个类型（Java 7+）：

catch (FileNotFoundException | InputMismatchException e) { ... }

5.7 throws 子句在继承中的限制

子类覆盖方法时，throws 列表不能变宽：

  • 可以相同；
  • 可以更少（删掉一些）；
  • 不能新增父类没声明的受检异常。
class ClassY {
    public void processFile(String fname) throws FileNotFoundException { ... }
}
class ClassZ extends ClassY {
    // 错误：父类只声明 FileNotFoundException，子类不能多声明 NegativeIntegerException
    public void processFile(String fname) throws FileNotFoundException, NegativeIntegerException { ... }
}

这保证了"用父类引用调用方法"的人，只需要处理父类声明过的异常（多态安全）。

5.8 finally 块

无论是否抛异常，finally 都会执行（即使 try 里有 return）。

Scanner inFile = null;
try {
    inFile = new Scanner(new File(fname));
    // ...
} catch (FileNotFoundException e) {
    System.out.println("Cannot open the file.");
} finally {
    if (inFile != null) inFile.close();     // 清理资源：一定会执行
    else System.out.println("inFile not open");
}

用途：关闭文件、释放资源。注意 catch 里不要重复关闭，否则可能 NullPointerException。

执行顺序（必考）：

  1. try 正常结束 → finally
  2. try 抛异常且有匹配 catch → catch → finally
  3. try 抛异常但没 catch 匹配 → finally 执行后异常继续向上抛
  4. try 里有 return → 先算返回值 → finally 执行 → 再真正返回（finally 里的 return 会覆盖它，别这么写）

5.9 异常传播（propagation）

main() --调用--> methodA() --调用--> methodB()   在 B 里抛异常
                                       |
       <--- 没有 catch，向上抛 --------+
main 也没有 catch → JVM 打印堆栈并终止程序
  • 每一层都可以 catch 处理，处理完就不再往上抛；
  • 都没处理 → 程序异常终止，打印 Exception in thread "main" ... 和堆栈（printStackTrace()）。

    at java.io.FileInputStream.open(Native Method)

6. 泛型（Topic 07）

6.1 为什么需要泛型

问题：写一个"能装任何类型"的容器，如果不用泛型，只能用 Object：

class Box {
    private Object content;
    public void set(Object o) { content = o; }
    public Object get() { return content; }
}

Box b = new Box();
b.set("hello");
String s = (String) b.get();   // 每次取出来都要强转，转错了就 ClassCastException

泛型（Generics）：让方法和类带类型参数，写一次代码，可复用于多种类型，且编译期就能检查类型。

  • 类型参数（type parameter）：<T>，占位符，代表"到时候再定的类型"。
  • 类型实参（type argument）：调用时真正填进去的类型，如 String、Integer。
  • 泛型编程（generic programming）：写一套代码，能复用于不同类型的对象。

6.2 泛型方法

public class Main {
    public static <T> void printTwice(T x) {
        System.out.println(x);
        System.out.println(x);
    }

    public static void main(String[] args) {
        printTwice("hello");   // T = String
        printTwice(1234);      // T = Integer（自动装箱）
        printTwice(4.0 / 3);   // T = Double
    }
}

语法位置：static 之后、返回类型之前写 <T>。这里的 T 只在这个方法内有效。

类型推断（type inference）：编译器看实参的类型，自动决定 T 是什么——所以调用时不用写 printTwice<String>("hello")。

6.3 泛型类

public class Pair<T> {
    private T first;
    private T second;

    public Pair() { }                              // first/second 默认 null
    public Pair(T x1, T x2) { first = x1; second = x2; }

    @Override
    public String toString() { return "(1)" + first + " (2)" + second; }
}

使用：每次用这个类，都要告诉它 T 是什么：

Pair<String>  p0 = new Pair<String>();
Pair<String>  p1 = new Pair<String>("hello", "cheers");
Pair<Boolean> p2 = new Pair<Boolean>(true, false);
Pair<Integer> p3 = new Pair<Integer>(123, 456);
Pair<Number>  p4 = new Pair<Number>(123, 456);
Pair<Object>  p5 = new Pair<Object>(123, "cheers");

System.out.println(p0);   // (1)null (2)null
System.out.println(p1);   // (1)hello (2)cheers
System.out.println(p5);   // (1)123 (2)cheers

注意：Pair<String> 和 Pair<Integer> 是同一个类的不同"参数化类型"，但它们共享同一份代码（类型擦除，见 6.6）。

构造器头不能写类型参数：

public <T> Pair() { }                    // 错误
public <T> Pair(T x1, T x2) { ... }      // 错误
public Pair(T x1, T x2) { ... }          // 正确

6.4 钻石语法（Diamond）

Java 7 起，new 后面的类型实参可以从左边推断，写成 <>：

Pair<String> p0 = new Pair<>();              // 等价于 new Pair<String>()
Pair<Boolean> p2 = new Pair<>(true, false);
ArrayList<Integer> list = new ArrayList<>(); // 最常见

编译器根据左边变量的类型填入类型参数。

6.5 类型参数的使用规则与命名习惯

  • 类型参数只能填引用类型，不能填基本类型：
ArrayList<int> list = new ArrayList<>();      // 编译错误
ArrayList<Integer> list = new ArrayList<>();  // 正确
  • 在泛型类/方法内部，T 可以当普通类型用：private T first; T getFirst() { ... }。
  • 填入具体类型后得到的类叫"实例化"（instantiation）：ArrayList<Integer>。
  • 命名习惯：
  • T — Type（第二、三、四个可用 S、U、V）
  • E — Element（集合框架常用）
  • K — Key，V — Value（Map 常用）
  • N — Number

6.6 类型擦除（Type Erasure）与常见陷阱

类型擦除：泛型只存在于编译期。编译后，T 会被替换成它的边界（没有边界就替换成 Object），并插入必要的强制转换。所以运行时没有泛型信息，也不会为每种类型生成新类 → 没有运行时开销。

// 源码
class Pair<T> { private T first; ... }

// 擦除后（大致）
class Pair { private Object first; ... }

由擦除导致的六条限制（考试爱考"下面哪个能编译"）：

限制 1：静态成员不能沾类型参数

class MobileDevice<T> {
    private static T os;       // 编译错误：静态字段全类只有一份，T 还没定
    private static int count;  // 可以：跟 T 无关
}

顺便记住一个陷阱：静态字段属于泛型类本身，不属于某个实例化类型。

class MobileDevice<T> {
    private static int count = 0;
    MobileDevice() { count++; System.out.println(count); }
}
new MobileDevice<Smartphone>();  // 1
new MobileDevice<Pager>();       // 2
new MobileDevice<TabletPC>();    // 3   ← 共享同一个 count

限制 2：不能 `new T()`

public static <E> void append(List<E> list) {
    E elem = new E();          // 编译错误：擦除后不知道 new 什么
    list.add(elem);
}

限制 3：不能创建泛型数组

String[] x1 = new String[3];                  // OK
Pair<String>[] x2 = new Pair<String>[3];      // 编译错误：Cannot create a generic array

限制 4：不能对参数化类型用 `instanceof` / 强转

if (list instanceof ArrayList<Integer>) { }   // 编译错误
Pair<Number> ln = (Pair<Number>) li;          // 编译错误（unchecked cast 也不允许直接写）

限制 5：擦除后签名相同的重载会冲突

public void print(Pair<String> p) { }
public void print(Pair<Integer> p) { }   // 编译错误：擦除后都是 print(Pair)

限制 6：不能定义泛型异常类

class MathException<T> extends Exception { }   // 编译错误
class QueueFullException<T> extends Throwable { }  // 编译错误

记忆口诀：静态字段、new T、泛型数组、instanceof、重载、异常 —— 这六样都不能用类型参数。

6.7 多个类型参数

class TwoTypePair<T1, T2> {
    private T1 first;
    private T2 second;

    public TwoTypePair(T1 firstItem, T2 secondItem) { first = firstItem; second = secondItem; }
    public void setFirst(T1 newFirst) { first = newFirst; }
    public void setSecond(T2 newSecond) { second = newSecond; }
    public T1 getFirst() { return first; }
    public T2 getSecond() { return second; }

    @Override
    public boolean equals(Object otherObject) {
        if (otherObject == null) return false;
        if (getClass() != otherObject.getClass()) return false;
        TwoTypePair<T1, T2> other = (TwoTypePair<T1, T2>) otherObject;
        return first.equals(other.first) && second.equals(other.second);
    }
}

TwoTypePair<String, Integer> x1 = new TwoTypePair<>("USD", 123);
TwoTypePair<String, Integer> x2 = new TwoTypePair<>("USD", 456);
TwoTypePair<String, Integer> x3 = new TwoTypePair<>("USD", 123);
x1.equals(x2);   // false
x1.equals(x3);   // true

6.8 类型参数的边界（Bounds）

限制 T 只能是某类及其子类：

class TwoBTypePair<T1 extends Class1, T2 extends Class2 & Comparable> { ... }
  • extends 后面可以跟多个上界，用 & 连接（第一个可以是类，其余必须是接口）。
  • 没有边界时，T 被擦除成 Object；有 extends Number 时被擦除成 Number。
public static <T extends Comparable<T>> T max(T a, T b) {
    return (a.compareTo(b) > 0) ? a : b;   // 因为有上界，才能调用 compareTo
}

7. 集合框架（Topic 08）

7.1 什么是集合框架

集合（collection）：一个"容器对象"，里面装一组元素。 框架（framework）：一套类/接口，构成开发高级功能的基础。

Java Collections Framework 支持四类容器：

  1. Set：一组不重复的元素；
  2. List：有序的元素序列（可重复）；
  3. Queue：按先进先出（FIFO）处理的队列；
  4. Map：键值对（key/value）。

两大接口树（必背）：

Collection<E>                      Map<K,V>
 ├── Set<E>                          ├── HashMap<K,V>
 │    ├── HashSet                     └── TreeMap<K,V>
 │    ├── LinkedHashSet
 │    └── SortedSet → TreeSet
 ├── List<E>
 │    ├── ArrayList
 │    ├── LinkedList
 │    └── Vector → Stack
 └── Queue<E>
      ├── LinkedList
      ├── PriorityQueue
      └── Deque → ArrayDeque

框架的三层设计（考试概念题）：

  • 接口（interfaces）：定义框架（Collection、Set、List、Map……）
  • 抽象类（abstract classes）：提供部分实现（AbstractCollection、AbstractList、AbstractSet……），让使用者少写代码
  • 具体类（concrete classes）：用具体数据结构实现（ArrayList、HashSet、HashMap……）

7.2 面向接口编程：变量声明成接口类型

import java.util.*;

        dataList.add(200);
        System.out.println(dataList);

        // 以后想换实现，只改一行：
        // dataList = new ArrayList<>();

好处：调用者只依赖接口，换数据结构不用改其他代码（这也是 DIP 的体现）。

List<Integer> dataList = new ArrayList<>();

7.5 HashSet：去重

Set<String> words = new HashSet<>();
Scanner in = new Scanner(new File("alice.txt"));
while (in.hasNext()) {
    String word = in.next();
    words.add(word);          // 重复的自动忽略
}
System.out.println(words);    // [.., .., ..] 所有不重复的词

哈希码（hash code）：一个整数，由对象状态计算出来，决定元素放在哈希表的哪个桶（bucket）。Java 的哈希表 = 数组 + 链表（桶）。

  • 查找时：先算 hashCode() 定位桶，再用 equals() 确认是不是同一个。
  • 所以放进 HashSet/HashMap 的对象，必须正确覆盖 `equals()` 和 `hashCode()`，且约定"equals 相等 → hashCode 必须相等"。

7.6 TreeSet：自动排序

Set<String> words = new TreeSet<>();

7.7 Comparator：自定义比较规则

问题：Comparable 只能定义"一种"比较方式（compareTo）。如果想按名字排序、又想按编号排序怎么办？

答案：Comparator 接口——把"比较规则"做成一个独立对象，传给集合。

public interface Comparator<T> {
    int compare(T a, T b);
}
class Product implements Comparable<Product> {
    private int part_number;
    private String product_name;
    public int compareTo(Product other) {
        return Integer.compare(part_number, other.part_number);  // 默认按编号
    }
    public String getName() { return product_name; }
    ...
}

// 按编号排序（用 Comparable）
SortedSet<Product> parts = new TreeSet<>();
parts.add(new Product("Widget", 4562));
parts.add(new Product("Toaster", 1234));
parts.add(new Product("Modem", 9912));
// [Toaster(1234), Widget(4562), Modem(9912)]

// 按名字排序（用 Comparator，写成匿名内部类）
SortedSet<Product> sortByName = new TreeSet<>(new Comparator<Product>() {
    public int compare(Product a, Product b) {
        return a.getName().compareTo(b.getName());
    }
});
sortByName.addAll(parts);
// [Modem(9912), Toaster(1234), Widget(4562)]

匿名内部类（anonymous inner class）：new Comparator<Product>() { ... } —— 没有名字、只用一次的类，直接实现接口。

7.8 PriorityQueue：优先队列

class Assignment implements Comparable<Assignment> {
    private int priority;    // 1 表示最高优先级
    private String name;
    public Assignment(String n, int p) { priority = p; name = n; }
    public int compareTo(Assignment other) {
        return Integer.compare(priority, other.priority);
    }
    public String toString() { return name + "(Priority:" + priority + ")"; }
}

PriorityQueue<Assignment> qToDo = new PriorityQueue<>();
qToDo.add(new Assignment("CS3342 Project", 2));
qToDo.add(new Assignment("CS3334 Survey", 1));
qToDo.add(new Assignment("CS2312 Assignment", 1));

System.out.println(qToDo);        // 顺序不保证！（底层是堆）
System.out.println(qToDo.remove());  // CS3334 Survey(Priority:1)
System.out.println(qToDo.remove());  // CS2312 Assignment(Priority:1)
System.out.println(qToDo.remove());  // CS3342 Project(Priority:2)

要点：

  • 底层是堆（heap），peek()/remove() 总是取出最小元素（按 compareTo 或 Comparator）。
  • toString() 打印出来的顺序不是出队顺序（堆的内部数组顺序），只能保证 remove() 顺序。
  • 同优先级时顺序不确定。

7.9 HashMap / TreeMap：键值对

Map<Integer, Product> parts = new HashMap<>();
parts.put(4562, new Product("Widget"));
parts.put(1234, new Product("Toaster"));
parts.put(9912, new Product("Modem"));

System.out.println(parts.get(9912));   // Modem

parts.put(9912, new Product("Router")); // 同一个 key 覆盖旧值
System.out.println(parts.get(9912));    // Router

// 遍历：先拿 keySet（键的集合），再逐个 get
Set<Integer> kSet = parts.keySet();
for (Integer k : kSet)
    System.out.printf("%s(%d) ", parts.get(k), k);

常用方法：

方法作用
put(k, v)放入/覆盖
get(k)取出，不存在返回 null
containsKey(k) / containsValue(v)是否存在
remove(k)删除
size() / isEmpty() / clear()基本操作
keySet()所有键的 Set（用于遍历）
values()所有值的 Collection
entrySet()所有键值对的 Set

HashMap vs TreeMap：

  • HashMap：无序，按 hashCode 定位（O(1) 平均）；key 必须正确实现 equals() 和 hashCode()。
  • TreeMap：按键排序（红黑树，O(log n)）；key 必须实现 Comparable 或提供 Comparator。
  • 两者都只对 key 做哈希/比较，value 随便。

JAVA 怎么定位一个 key：先用 hashCode() 找到桶，再用 equals() 确认。所以"两个对象 equals 相等，hashCode 必须相等"。

7.10 数组与集合互转

（1）数组 → 集合包装（Arrays.asList）：

System.out.println(Arrays.toString(nArr));  // [Marian, Kit, Jason]

要点：asList 返回的是轻量包装器，底层还是原数组；可以 set，不能 add/remove（大小固定）。

（2）集合 → 数组拷贝（toArray）：

Collection<String> c = new ArrayList<>();
c.add("Helena"); c.add("Kit"); c.add("Jason");

String[] arr = c.toArray(new String[1]);   // 新数组，长度按需要扩展
arr[0] = "Tom";
System.out.println(c);                     // [Helena, Kit, Jason] ← 集合不受影响
System.out.println(Arrays.toString(arr));  // [Tom, Kit, Jason]

要点：toArray 是真正的拷贝，改数组不影响集合。

7.11 Collections 工具类：常用算法

List<String> c = new ArrayList<>();
c.add("Helena"); c.add("Kit"); c.add("Jason");

Collections.shuffle(c);                  // 随机打乱
Collections.sort(c);                     // 升序排序
Collections.binarySearch(c, "Helena");   // 二分查找，返回下标（必须先排序）
Collections.min(c);                      // 最小元素
Collections.max(c);                      // 最大元素
Collections.reverse(c);                  // 反转
Collections.rotate(c, 2);                // 循环右移 2 位
Collections.frequency(c, "Helena");      // 出现次数
Collections.disjoint(c, c.subList(0,1));  // 两个集合是否没有交集
Collections.swap(c, 0, 1);               // 交换两个位置

注意：Collections.sort / binarySearch 要求元素实现 Comparable（或传入 Comparator）；binarySearch 前必须已排序。

8. OOP 关系、UML 画图与设计原则（Topic 09）

这一章专门对付考试的 Drawing（画图） 和 Conceptual description（概念描述） 题。
画图题的评分点通常是：类框是否正确、关系箭头是否正确、多重性（1 / *）是否标注、可见性符号是否用对。

8.1 类图（Class Diagram）基本符号

一个类画成一个三格矩形：

+----------------------------------+
|            Employee              |   ← 类名（抽象类用斜体，接口标 «interface»）
+----------------------------------+
| - id : String                    |   ← 字段（属性）
| - name : String                  |
| - salary : double                |
| # hireDay : Day                  |
+----------------------------------+
| + getName() : String             |   ← 方法（操作）
| + getSalary() : double           |
| + raiseSalary(percent : double)  |
+----------------------------------+

可见性符号（必背）：

符号含义
+public
-private
#protected
~package-private（无修饰符）

其他约定：

  • 静态成员加下划线：+ getInstance() : PersonnelOffice（下划线表示 static）。
  • 抽象类/抽象方法用斜体（手写时可以在类名后写 {abstract}）。
  • 接口在类名上方标 «interface»。
  • 字段格式：可见性 名字 : 类型；方法格式：可见性 名字(参数) : 返回类型。

8.2 六种关系（画图题核心）

（1）继承 / 泛化（Inheritance / Generalization）—— "is-a"

画法：实线 + 空心三角箭头，箭头指向父类。

   Employee           ← 父类
      △
      │  （实线、空心三角）
      │
   Manager            ← 子类

代码：class Manager extends Employee

（2）实现（Realization）—— "implements-a"

画法：虚线 + 空心三角箭头，箭头指向接口。

   «interface»
     IGrade
        △
        ┆  （虚线、空心三角）
        ┆
    Exercise

代码：class Exercise implements IGrade

（3）依赖（Dependency）—— "uses-a"

定义：如果B 变了，A 可能也要改/重新编译，就说 A 依赖 B。

画法：虚线 + 普通箭头（开口箭头），箭头从使用者指向被使用者。

   Order  ┈┈┈>  Customer        （Order 用到了 Customer）
   A      ┈┈┈>  B

什么时候算依赖（Topic09 列了 3 种）：

  1. B 是 A 的父类，或 B 是 A 实现的接口；
  2. B 是 A 的字段类型、方法参数类型、局部变量类型；
  3. A 的代码里调用了 B 的方法/字段，或在 A 里 new 了 B。
class A extends B { }                       // 依赖（也是继承）
class A implements B { }                    // 依赖（也是实现）
class A { private B b; }                    // 依赖
class A { public void handleIt(B b) { } }   // 依赖
class A { public void f() { B b = Company.getB(); b.xxx(); } }  // 依赖
class A { public void f() { (new B()).xxx(); } }                // 依赖

（4）关联（Association）—— "knows-a"

定义：对象之间长期的"认识"关系，通常实现为对象字段。

画法：实线（可带普通箭头表示导航性），两端标多重性。

   Order ───────────── Customer
     *                    1
   （一个 Customer 可以有多个 Order）

两种实现方向（取决于你的意图）：

// 方向 (i)：Order 知道 Customer
class Order { private Customer cus; }

// 方向 (ii)：Customer 知道所有 Order（代码同上，(ii) 只是多一个 list）
class Customer { private ArrayList<Order> orders; }

多重性（multiplicity）写法：

标记含义
1恰好一个
0..1零或一个
*零或多个
1..*一个或多个
0..* 或 *零或多个

读法：看线另一端的数字。Order * ──── 1 Customer 表示"一个 Order 对应一个 Customer；一个 Customer 对应多个 Order"。

关联类（Association Class）：关联本身还有属性时，要单独建一个类。

   Employee * ────── * Project
              │
           WorksOn          ← 关联类
           - hours
           - startDate
class WorksOn {
    private Employee e;
    private Project p;
    private int hours;
    private Day startDate;
}

（5）聚合（Aggregation）—— "has-a"（弱）

画法：实线 + 空心菱形，菱形在"整体"那一端。

   Group ◇──────── Member
     1              *

含义："组里有成员"，但成员可以独立存在（组解散了，成员还在）。语义比较模糊，聚合本身也是一种关联。

（6）组合（Composition）—— "has-a"（强，同生共死）

画法：实线 + 实心菱形，菱形在"整体"那一端。

   Polygon ◆──────── Point
      1              *

含义：

  • 单一所有者：A 拥有 B；
  • 生命周期一致：A 销毁，B 也销毁（A 负责创建和控制 B 的生命）。

课堂 FAQ 的经典例子：

多边形 p1 的一个顶点是 (123,45)，圆 c1 的圆心恰好也是 (123,45)。它们应该指向两个不同的 Point 对象，而不是共享同一个。

因为组合关系下"点"属于某一个图形，不能共享。

聚合 vs 组合速记：

聚合 Aggregation组合 Composition
菱形空心 ◇实心 ◆
强度弱强
生命周期各自独立整体控制部分
例子Group–Member、Team–PlayerPolygon–Point、Order–OrderLine、House–Room

⚠️ 考试提醒：这几种关系经常不止一个答案正确。课堂原话："More than one could be correct! Therefore, see which can best match your intention (what to tell)." 答题时写清你的理由即可（例如"我用组合，因为 Point 由 Polygon 创建并随其销毁"）。

8.4 画图题的答题步骤（照着做不丢分）

  1. 读需求，圈名词 → 候选类（Student、Course、Offering……）。
  2. 圈动词 → 候选方法（register、listStudents……）。
  3. 找 "is-a" → 有没有父子类（Employee / Manager；Person / Student）。
  4. 找 "has-a" → 谁包含谁（University 有 Course；Course 有 Offering）。
  5. 定多重性 → 一对一？一对多？多对多？（多对多通常要拆成关联类）
  6. 画框：类名 + 关键字段（带 -）+ 关键方法（带 +）。
  7. 连线：按 8.2 的六种关系画线、箭头、菱形。
  8. 标多重性：1、*。
  9. 检查：每个关系的两端数字是否说得通；有没有把"继承"画成"关联"。

8.6 五个 OO 术语（概念题标准答案）

术语定义Java 中的体现
Encapsulation（封装）把数据和操作数据的方法打包在一起，隐藏实现细节private 字段 + public 方法
Abstraction（抽象）规定框架、隐藏实现；告诉使用者"做什么"而不是"怎么做"接口、抽象方法
Generalization（泛化）把公共结构和行为提到继承层次的更高层抽出 Employee 父类
Realization（实现）为抽象蓝图提供具体实现子类实现抽象方法 / 实现接口
Delegation（委托）一个对象把请求转发给另一个对象，由后者代劳class Cat { private SoundBehaviour s; void makeSound(){ s.makeSound(); } }

Delegation 的例子（课堂原码）：

interface SoundBehaviour { void makeSound(); }
class MeowSound implements SoundBehaviour { public void makeSound() { System.out.println("Meow"); } }
class RoarSound implements SoundBehaviour { public void makeSound() { System.out.println("Roar!"); } }

class Cat {
    private SoundBehaviour sound = new MeowSound();
    public void makeSound() { sound.makeSound(); }              // 委托
    public void setSoundBehaviour(SoundBehaviour newSound) { sound = newSound; }  // 运行时换行为
}

优点：可以在运行时组合行为，常用来替代继承（继承是编译期固定的）。

8.7 内聚（Cohesion）与耦合（Coupling）

好设计 = 高内聚 + 低耦合。

  • 耦合（coupling）：模块之间互相依赖的程度。两个类中改一个会导致另一个也要改，就是耦合。
  • 高耦合 ✘：循环依赖（A→B→C→A）、牵一发动全身。
  • 低耦合 ✔：模块之间通过接口/少量接口通信。
  • 内聚（cohesion）：一个类/方法只做一件事的程度。
  • 低内聚 ✘：一个类既处理 s 又处理 t，什么都干。
  • 高内聚 ✔：拆成 ClassA（只管 s）和 ClassC（只管 t）。

常见错误："类/方法太少" —— 把太多职责塞进一个类，导致低内聚。

8.8 三条设计原则（考概念题）

LSP（Liskov Substitution Principle，里氏替换原则）

子类对象必须能够替换父类对象，而程序行为不变。

反例：BatteryDuck extends Duck —— 电池鸭继承鸭子（为了复用代码），但它不会 eat()，行为不一致，替换后就出错。这说明继承用错了（只是"部分代码复用"，不是真 is-a）。

DIP（Dependency Inversion Principle，依赖倒置原则）

高层模块不应该依赖低层模块，两者都应该依赖抽象；抽象不应该依赖细节，细节应该依赖抽象。

反例：Main 直接 new 具体的 SalariedEmployee、HourlyEmployee，每加一种员工就要改 Main。 正例：Main 只依赖 Employee（抽象），新增子类不用改 Main（Topic04 p12 的例子）。

OCP（Open-Closed Principle，开闭原则）

模块应该对扩展开放，对修改关闭。

也就是说：加新功能时应该新增代码，而不是改已经能跑的旧代码。

反例（Lab06 的 Approach 1）：

public void action() {
    if (happyLevel == HAPPY) System.out.println("Willing to help others");
    else if (happyLevel == HALF) System.out.println("Living well");
    else System.out.println("Seek positive growth");
    // 新增一种心情 → 必须改这个 if-else → 违反 OCP
}

反例（Approach 2，用继承）：

class HappyPerson extends Person { ... }
// 心情变了 → 必须重建对象：m = new UnhappyPerson(); 还要更新所有引用 → 违反 OCP

正解（State 模式，下一章）：把"心情"做成独立的状态对象，Person 只持有一个 HappyLevel 引用，新增心情 = 新增一个类，不改 Person。

8.9 重构（Refactoring）

定义：不改变外部行为的前提下，改善代码结构。

  • 症状（code smell）：代码越写越丑、越来越难改。
  • 手段：去掉不健康的依赖、拆分类/方法的职责、消除重复代码。
  • 目标：让代码保持干净、简单、易表达。

考点：refactoring 的定义关键词是"不改变外部行为（without changing its external behavior）"。

9.1 Singleton（单例模式）

要解决的问题：某个类在整个程序里只应该有且只有一个对象（例如：人事办公室、系统日期、配置管理器、打印队列），并且要提供一个全局访问点。

三要素（必背）：

  1. private static 字段保存那唯一实例；
  2. private 构造器，防止外人 new；
  3. public static 方法 getInstance() 返回该实例。

实现（饿汉式，Lab05 Q5 的原版）：

public class PersonnelOffice {
    private ArrayList<Employee> allEmployees;

    // ① 唯一实例，类加载时就创建
    private static PersonnelOffice thePO = new PersonnelOffice();

    // ② 私有构造器：外面不能 new
    private PersonnelOffice() {
        allEmployees = new ArrayList<Employee>();
    }

    // ③ 全局访问点
    public static PersonnelOffice getInstance() { return thePO; }

    public void addEmployee(Employee e) { allEmployees.add(e); }
    public void listAll() { for (Employee e : allEmployees) System.out.println(e); }
}

使用：

PersonnelOffice po = PersonnelOffice.getInstance();   // 永远拿到同一个对象
PersonnelOffice po2 = PersonnelOffice.getInstance();
System.out.println(po == po2);                        // true
// PersonnelOffice p3 = new PersonnelOffice();        // 编译错误：构造器是 private

UML 结构：

+----------------------------------+
|          PersonnelOffice         |
+----------------------------------+
| - thePO : PersonnelOffice        |   ← 下划线：static
| - allEmployees : ArrayList       |
+----------------------------------+
| - PersonnelOffice()              |   ← private 构造器
| + getInstance() : PersonnelOffice|   ← static
| + addEmployee(e : Employee)      |
+----------------------------------+

懒汉式（lazy，了解即可）：第一次调用时才创建。

private static PersonnelOffice thePO = null;
public static PersonnelOffice getInstance() {
    if (thePO == null) thePO = new PersonnelOffice();
    return thePO;
}

考试常问：

  • "为什么要 private 构造器？" → 防止外部再创建实例，保证唯一性。
  • "static 字段起什么作用？" → 全类共享一份，保存唯一实例。
  • "getInstance() 为什么是 static？" → 不通过对象调用（还没有对象），只能通过类名调用。
  • "单例有什么缺点？" → 全局状态、难测试、多线程要注意同步（了解）。

9.2 State（状态模式）

要解决的问题：一个对象的行为随内部状态改变而改变，而且以后可能增加新状态。如果用 if-else 判断状态，每加一种状态就要改原来的代码 → 违反 OCP。

三个版本的对比（Lab06 讲义，考试最爱考"为什么前两个不好"）：

Approach 1：if-else（差）

class Person {
    private int happinessLevel;   // 0=happy, 1=half, 2=unhappy
    public void action() {
        if (happinessLevel == 0) System.out.println("Willing to help others");
        else if (happinessLevel == 1) System.out.println("Living well");
        else System.out.println("Seek positive growth");
    }
}

缺点：新增"非常开心"状态 → 必须修改 action() 的 if-else 块，旧代码被打开修改（违反 OCP）。

Approach 2：继承（也差）

class HappyPerson extends Person { public void action() { ... } }
class UnhappyPerson extends Person { public void action() { ... } }

缺点：状态是会变的。心情从"不开心"变"开心"，就必须 m = new HappyPerson(); 重建对象，还要把所有指向它的引用（如 company.changeManager(m)）全部更新 —— 非常麻烦。

Approach 3：State 模式（好）

把"状态"抽成一个接口，每个具体状态一个类；Person 持有状态对象，行为委托给它。

interface HappyLevel {
    void action();                    // 只声明，不实现
}

class HappyCharacter implements HappyLevel {
    public void action() { System.out.println("Willing to help others"); }
}
class HalfCharacter implements HappyLevel {
    public void action() { System.out.println("Living well"); }
}
class UnhappyCharacter implements HappyLevel {
    public void action() { System.out.println("Seek positive growth"); }
}

class Person {
    private HappyLevel happyLevel;    // 组合：当前状态
    private String name;

    public Person(String n, HappyLevel h) { name = n; happyLevel = h; }

    public void setHappyLevel(HappyLevel h) { happyLevel = h; }   // 换状态：换对象，不重建 Person

    public void action() { happyLevel.action(); }                 // 委托
}

使用：

Person p = new Person("Mary", new HappyCharacter());
p.action();                       // Willing to help others

9.3 Command（命令模式）

要解决的问题：把"一个请求/操作"封装成对象，从而可以记录、排队、撤销（undo）、重做（redo）。

Lab08 的场景：员工工资管理系统，用户输入 1 加薪、2 列出、3 undo、4 redo……每次操作都要能撤回。

三要素：

  1. Command 接口：execute()（执行）和 undo()（撤销）；
  2. 具体命令类：每个操作一个类，保存"执行所需的数据"；
  3. Invoker：持有命令历史（两个栈：undo 栈、redo 栈）。
interface Command {
    void execute();
    void undo();
}

// 具体命令：给某人加薪
class AddSalaryCommand implements Command {
    private Company company;
    private Employee target;
    private double amount;

    public AddSalaryCommand(Company c, Employee e, double amt) {
        company = c; target = e; amount = amt;
    }
    public void execute() { target.setSalary(target.getSalary() + amount); }
    public void undo()    { target.setSalary(target.getSalary() - amount); }
}

撤销/重做的核心逻辑（考试可能让你写）：

class Invoker {
    private ArrayList<Command> undoList = new ArrayList<>();
    private ArrayList<Command> redoList = new ArrayList<>();

    public void execute(Command c) {
        c.execute();
        undoList.add(c);        // 新操作进入 undo 栈
        redoList.clear();       // 做新操作后，redo 历史作废（Lab08 Q0 第 7 步）
    }

    public void undo() {
        if (undoList.isEmpty()) return;
        Command c = undoList.remove(undoList.size() - 1);
        c.undo();
        redoList.add(c);        // 被撤销的操作移到 redo 栈
    }

    public void redo() {
        if (redoList.isEmpty()) return;
        Command c = redoList.remove(redoList.size() - 1);
        c.execute();
        undoList.add(c);        // 重做后回到 undo 栈
    }
}

Lab08 Q0 的六个结论（原题答案）：

  • (a) undo 可用 ⇔ undo-list 非空；
  • (b) redo 可用 ⇔ redo-list 非空；
  • (c) 每次 undo，被撤销的动作加入 redo-list；
  • (d) 每次 redo，被重做的动作回到 undo-list；
  • (e) 每次新的编辑动作加入 undo-list；
  • (f) 做了新编辑后，redo-list 被清空。

"static ArrayList" 的用法（Lab08 Q0.II）：

class Pocket {
    private Object thing;
    private static ArrayList<Pocket> createdPockets = new ArrayList<>();  // 全类共享的登记表

    public Pocket(Object t) {

    }

10. 递归与"画内存图"（Lab03/04/05/07/08/11）

10.1 递归的三要素

递归（recursion）：一个方法调用自己来解决问题。

写递归只需要想清楚三件事：

  1. base case（基准情形）：什么时候不再递归，直接返回；
  2. recursive case（递归情形）：把问题缩小，调用自己；
  3. 组合：用子问题的结果拼出当前问题的结果。

例：按位打印一个整数（Lab04 Q1）

void showDigits(int n) {
    if (n < 10) {                 // base case
        System.out.print(n + " ");
    } else {
        showDigits(n / 10);       // 先打印高位（递归）
        System.out.print(n % 10 + " ");   // 再打印最低位
    }
}

showDigits(567) 的输出：5 6 7。 showDigits(9) 的输出：9。

执行过程（调用栈，必会画）：

showDigits(567)
  ├─ showDigits(56)
  │    ├─ showDigits(5) → 打印 "5 "
  │    └─ 打印 56%10 = "6 "
  └─ 打印 567%10 = "7 "

输出顺序 = 5 6 7（先递归、后打印 → 正序；先打印、后递归 → 倒序）。

10.2 递归方法的追踪（tracing）技巧

考试给一段递归代码问输出，按这四步做：

  1. 标出 base case，写出它返回什么、打印什么；
  2. 写出递归调用链（参数怎么变小）；
  3. 画调用栈：从上往下压栈，到 base case 开始返回；
  4. 按返回顺序写输出/返回值（打印语句在递归前还是后，决定顺序）。

经典对比：

// 正序
void f(int n) { if (n < 10) print(n); else { f(n/10); print(n%10); } }
// 倒序
void g(int n) { if (n < 10) print(n); else { print(n%10); g(n/10); } }

f(123) → 1 2 3；g(123) → 3 2 1。

11.3 概念题答题模板

问："什么是封装？有什么好处？"

封装是把数据和操作数据的方法组合在同一个类里，并用 private 隐藏字段、只通过 public 方法对外提供访问。好处有三点：(1) 防止数据被外部误改；(2) 出错时容易定位（只有本类方法能改数据）；(3) 实现可以替换而不影响使用者（例如 Day 从三个 int 改成 yyyymmdd）。

问："接口和抽象类有什么区别？什么时候用哪个？"

用 4.3 的表格答 3 条差异（继承数量、方法实现、字段/构造器），再补"紧密相关的类共享代码用抽象类；不相关的类实现能力用接口"。

问："重载和覆盖的区别？"

重载是同一个类里方法名相同、参数不同，编译期决定；覆盖是子类重新实现父类的同名同参数方法，运行期动态绑定。

问："checked 和 unchecked 异常？"

checked 是 Exception 的子类但不是 RuntimeException 的子类，编译器强制 catch 或 throws（如 FileNotFoundException）；unchecked 是 RuntimeException 及其子类（如 NullPointerException），编译器不强制。

11.5 刷题 B 组：找错（Lab02 Q1 风格）

下面这段代码有 10 处错误（语法 + 逻辑），先自己找，再看答案。

public class Main {
    public static final int WIDTH = 12;
    public static final int HEIGHT = 8;

    public static void count_0_to_100(int [HEIGHT][WIDTH] A) {
        int count = 0;
        for(int y = 0, y < HEIGHT, y+1) {
            for (int x = 0, x < WIDTH, x+1)
                if(0 <= A[y][x] <= 100)
                    count+1;
        }
        System.out.print("The count is: " count);
    }

    public static void main(String[] args) {
        int[HEIGHT][WIDTH] values ;
        ...
        count_0_to_100(values[HEIGHT][WIDTH]);
    }
}

答案（逐条，共 10 处）：

  1. 参数类型 int [HEIGHT][WIDTH] A → int[][] A（Java 的数组类型不写长度）。
  2. 外层 for(int y = 0, y < HEIGHT, y+1)：两个逗号应为分号 → for (int y = 0; y < HEIGHT; y++)。
  3. 外层 y+1 只是算了个值，不会让 y 增加 → y++。
  4. 内层 for (int x = 0, x < WIDTH, x+1)：同样两个逗号应为分号。
  5. 内层 x+1 → x++。
  6. 0 <= A[y][x] <= 100 不能连写比较 → A[y][x] >= 0 && A[y][x] <= 100。

public class Day {
    private int year, month, day;

    public Day(int y, int m, int d) { year = y; month = m; day = d; }

    private static boolean isLeapYear(int y) {
        return (y % 400 == 0) || (y % 4 == 0 && y % 100 != 0);
    }
    private static int daysInMonth(int y, int m) {
        switch (m) {
            case 2:  return isLeapYear(y) ? 29 : 28;
            case 4: case 6: case 9: case 11: return 30;
            default: return 31;
        }
    }

    public void advance() {
        if (day < daysInMonth(year, month)) {
            day++;
        } else {
            day = 1;
            if (month == 12) { month = 1; year++; }
            else month++;
        }
    }

    public void previous() {
        if (day > 1) {
            day--;
        } else {
            if (month == 1) { month = 12; year--; }
            else month--;
            day = daysInMonth(year, month);
        }
    }

    @Override
    public String toString() {
        final String[] M = {"Jan","Feb","Mar","Apr","May","Jun",
                            "Jul","Aug","Sep","Oct","Nov","Dec"};
        return day + " " + M[month - 1] + " " + year;
    }
}

12.2 参考答案

Q1

(a) JRE 是运行环境，供用户运行 Java 程序；JDK 是开发工具包，= JRE + 编译器（javac）、调试器等，供程序员开发。JVM 是 Java 虚拟机：运行时装载 .class 字节码，把它解释/编译成当前操作系统的调用，从而实现"一次编译，到处运行"。

(b) 封装 = 把数据和操作数据的方法放在同一个类中，用 private 隐藏字段，只通过 public 方法访问。好处：① 防止外部误改数据；② bug 容易定位（只有本类方法能改数据）；③ 实现可替换（如 Day 从 3 个 int 改成 1 个 int，外部代码不变）。

(c) checked：Exception 的子类但非 RuntimeException 的子类，编译器强制 catch 或 throws，如 FileNotFoundException；unchecked：RuntimeException 及其子类，编译器不强制，如 NullPointerException。

(d) 重载：同一个类中，方法名相同但参数列表不同，编译期根据签名决定调用哪个；覆盖：子类重新实现父类同名同参数的方法，运行期根据对象实际类型动态绑定。返回类型不算签名的一部分。

(e) 动态绑定 = 运行时根据对象的实际类型选择要执行的实例方法。只适用于非静态的实例方法；字段和 static 方法按变量声明类型在编译期决定，不做动态绑定。

  • <T>、类型擦除、钻石 <>
  • 只能填引用类型
  • 六不能：static 字段、new T、泛型数组、instanceof、重载、泛型异常
  • 边界 T extends Number & Comparable

集合

  • Collection（Set/List/Queue）与 Map 两棵树
  • HashSet 无序去重、TreeSet 排序、HashMap 键值、PriorityQueue 取最小
  • Comparable（类内）vs Comparator（类外、匿名内部类）
  • Arrays.asList 是视图不能增删；toArray 是拷贝
  • Collections.sort/shuffle/binarySearch/reverse/rotate/frequency/disjoint
  • HashMap 的 key 要 equals + hashCode

UML

  • 继承：实线 + 空心三角 → 父类
  • 实现：虚线 + 空心三角 → 接口
  • 依赖：虚线 + 开口箭头
  • 关联：实线（可带箭头）
  • 聚合：空心菱形在整体端
  • 组合：实心菱形在整体端
  • 多重性：1 / / 0..1 / 1..
  • 可见性：+ public、- private、# protected、~ package

原则与模式

  • 高内聚、低耦合
  • LSP：子类可替换父类
  • DIP：依赖抽象，不依赖细节
  • OCP：对扩展开放，对修改关闭
  • Singleton：private static 实例 + private 构造器 + getInstance
  • State：状态接口 + 具体状态类 + Context 委托（符合 OCP）
  • Command：execute/undo + undo/redo 两个栈

13.4 最容易丢分的 15 个点

  1. 比较字符串用了 ==
  2. nextInt() 后直接 nextLine()
  3. 忘了 arr.length 没有括号
  4. 构造器写了返回类型 void
  5. 子类构造器忘了 super(...)（父类没有无参构造器时）
  6. 覆盖 equals 参数写成具体类而不是 Object
  7. 以为字段会动态绑定
  8. 以为 static 方法能被覆盖（其实是隐藏）
  9. catch (Exception e) 写在具体异常前面
  10. 泛型里写了 new T() 或 ArrayList<int>
  11. Arrays.asList 之后 add() 运行时报错
  12. 画图时把对象数组的格子画成对象而不是箭头
  13. 聚合/组合的菱形方向画反（菱形永远在"整体"那端）
  14. 写 Singleton 时构造器忘了 private
  15. 递归忘了 base case / 打印顺序搞反
